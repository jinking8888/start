# start
### 1. 关于仓库使用说明。
- 通过终端命令使用：来自powershell或cmd（VScode内置终端也可）
- 通过git命令操作。

### 2. git命令具体操作。
- 禁止直接使用main主分支传东西。
-  1. 首先操作是在终端申明身份：
``` git config global user.name "你的github用户名"
    git config global user.email "你的github邮箱"
    # 这两条命令是在全局环境中绑定本地身份信息。如果身份信息与github相同，则github能够自动识别到对应账号并自动绑定。
    # 上述命令到引号处终止则是查询当前身份信息。如下：
    git config global user.name # 查询当前的全局用户名
```
- 2. 仓库与本地仓库说明：
    - 本地仓库：来自git init的初始化创建在本地工作文件夹的仓库
    （在某文件夹中运行 git init git会自动在当前文件夹创建本地仓库记录）
    - git add . （提交当前文件所有文件到记录）
    - git commit -m "提交说明" （提交记录到本地仓库）
    ##### 即代码保存到仓库需要两次提交，在操作意义上是第一次提交是将文件添加到记录，第二次提交是将记录提交到本地仓库。
    - git status （查看当前文件夹中各项文件的git状态（自上次git commit后是否改动是否再次add等）
    - git log （查看提交记录）（查看自己的提交记录
    ##### 关于分支：
    - git branch （查看当前已有分支）（分支的意义是commit保存所在位置）  
    **不同分支不会相互影响，不会相互覆盖**
    - git branch -b 新分支名 （创建新分支并切换到新分支） （默认操作的分支为主分支main/master）（当然有对应命令是只创建分支但不转到此分支、切换到指定分支）
    **当切换到对应分支后，提交操作会将记录提交到对应分支**

- 3. 远程仓库：
    - git remote add origin 仓库地址 （将本地仓库与远程仓库进行绑定），仓库地址为github页面获得的仓库url，绑定后才能进行获取仓库内文件和向仓库上传文件的操作
    - git push -u origin 分支名 （将本地分支提交到远程仓库,如果没有此分支则自动创建此分支。 *禁止直接使用main主分支传东西*）
    - git pull origin 分支名 （从远程仓库拉取对应分支的最新代码到本地）（当多人协作时，提交前先拉取远程仓库的最新代码，避免冲突）
    - git merge 分支名 （合并对应分支到当前分支）  
    **合并时，关于代码修改冲突，需要进行手动解决，需要重新提交到本地仓库。因此不要随便合并，会把分支记录搞丢**

    - git clone 仓库地址 （克隆远程仓库到本地） 克隆是最简单的操作，自动包括：拉取全部文件到本地、绑定远程仓库、切换到对应分支全过程。

- 4. 提交说明： 
    - 在本地要手动撰写gitignore文件，命名是 .gitignore 在此文件中写入的文件名，会在git add和git commit中被忽略到。  
    防止本地的各类文件被提交到远程仓库。（尤其是包括虚拟环境配置等在内的东西都不要传到分支上，要不然拉取下来会崩溃） 可以让AI代写。

- 5. 虚拟环境说明。
    在本地局部环境内才能运行的代码，要上传到仓库后，为了保证其他人拉取到本地也能自己搭建对应虚拟环境，需要撰写对应说明文件。（pip或uv都会自动产生，只要在最初下载依赖时操作规范就自动有了）
     （但对于工作文件夹的外部环境可能不保证有，因此有时需要再撰写）
     通常是uv.lock或project.toml文件。(这些文件在其他人拉取后，使用对应终端命令就可以直接根据这些文件一键全自动搭建与原本上传者的本地环境一致的虚拟环境)
